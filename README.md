# 软件使用时长监测

记录 Windows 上各个软件的使用时长，**区分前台时长与后台真实活跃时长**，数据只存本机、**全程不联网**。

> 状态：**v0.7.4**。源码运行或打包版（release 提供 full / lite 双包）均可使用。
> v0.7 新增：每日摘要（开机托盘气泡 + 窗口横幅，可关）、单应用用时提醒（右键设阈值）、悬浮窗贴边停靠（拖到屏缘缩成一条，悬停恢复）。
> v0.7.1 修复：统计窗口数据不自动加载/切换周期不刷新（init 接线被误卷进 helper 成死代码）；提醒口径与统计页统一按组计算；config 写入改精确键防跨进程互覆盖。
> v0.3 新增：界面语言切换（中英双语）、桌面悬浮窗（独立进程，默认关）。

## 它和别的同类工具差在哪

| | 本程序 | 常见的同类工具 |
|---|---|---|
| **后台时长** | ✅ 按"确有真实活动"判定（CPU 或磁盘 I/O 超阈值），挂一天不算在用 | ❌ 多数只统计前台，或把"进程活着"当"在用" |
| **窗口标题** | **完全不采集**（识别软件靠 exe 路径） | 常常会记录标题——里面可能带文件名、聊天对象、搜索词 |
| **联网** | 源码里没有任何网络代码 | 常有云端同步 / 使用统计 / 更新检查 |
| **常驻内存** | 守护进程约 **32 MB**（不加载 Qt） | Electron / Qt 一体常驻通常在 100 MB 以上 |
| **不可监测项** | 明确标出并从源头不采集，界面锁死 | 通常不区分 |
| **权限** | 普通用户权限即可，**不提权** | 有些要求以管理员运行 |

## 设计要点

**两种进程角色，共用一个脚本**（`src/app.py`）：

- 无参数 → 采集守护进程。**刻意不加载 PySide6**，常驻内存约 32 MB。
- `--gui` → 统计窗口，独立进程、关窗即退出、内存随之释放。
- `--smoke` → 自检模式，跑几秒输出链路诊断。
- `--overlay` → 桌面悬浮窗，独立轻进程（设置页开关控制，默认关）。

**分层严格单向**（由 `tools/test_arch.py` 自动断言，反向依赖会直接失败）：

```
collect → apps → track → data → ui_*
```

UI 层不许出现任何 SQL，只能调用 `data.py` 暴露的查询函数。
界面显示文案统一走 `i18n.py`（中英双语，设置页切换、重启生效）；
业务逻辑只用英文 key 判断，缺 key 回落中文再回落 key（不静默吞错）。

**关键正确性设计**：

- 前台用 `SetWinEventHook` 事件驱动（毫秒级），1 秒轮询兜底；
  **无输入空闲超 5 分钟截断前台段**（不锁屏走人不会被记成一直在用）
- 后台时长用滞后计数（连续 2 轮活跃才开段、连续 3 轮不活跃才收尾）+ 相邻片段合并，
  避免 1 秒级采样产出大量碎片
- 同一应用多进程的时长按**时间轴并集**计算，避免多进程应用虚高数倍
- 锁屏 / 休眠时暂停计时——**前台与后台一并停记**（锁屏期间整个采样循环跳过，
  后台 IO/音频判定也不跑，09-30 真库验证：长锁屏后零片段）；**唤醒后重置全部
  CPU/IO 基线**（否则休眠时长会被算成后台活跃）
- 同一应用多进程/家族（如游戏本体+启动器、微信+内嵌浏览器）在统计里**归并为
  一条**：内置预设 + 保守路径爬根，只对多成员组生效（宁少归并不误归并），
  归并后的时长按组内所有进程区间的大并集计算
- 跨零点的片段在写库时按天拆开

## 目录结构

```
src/            程序源码（15 个文件，纯代码约 2930 行，上限 3000）
  app.py        入口：守护 / 统计窗口 / 自检 / 悬浮窗
  collect.py    采集：前台事件 + 后台活跃判定
  apps.py       进程身份、第三方判定、可监测性判定
  track.py      片段生成、合并、区间并集
  audio.py      音频会话检测（后台判活 + 看视频 AFK 豁免）
  data.py       存储（唯一允许 sqlite3.connect 的地方）
  schema.py     表结构 DDL
  tray.py       原生托盘（不依赖 Qt）
  sysmsg.py     消息循环与电源/会话事件
  winutil.py    共用 Win32 封装
  ui_main.py    统计窗口（含手绘图表）
  ui_scope.py   监测范围页 + 设置页
  ui_overlay.py 桌面悬浮窗（独立轻进程，默认关）
  i18n.py       中英文案表（界面语言切换）
  config.py     全部阈值与配置的唯一入口
tools/          脚本与测试（见下表）
```

## 自检与验证

| 脚本 | 做什么 |
|---|---|
| `tools/test_arch.py` | **架构约束**：依赖方向、单文件/单函数行数、继承层数、SQL 位置、阈值单点 |
| `tools/selftest.py` | **131 项**逻辑与安全回归（含不可监测项强制锁定、多进程并集、跨天切分、音频判活、自启红线、片段保留、i18n 表一致性、悬浮窗偏好、Store 韧性、依赖声明） |
| `tools/audit.py` | **隐私与安全自证** 9 项，输出可直接贴出来的报告 |
| `tools/bench_mem.py` | 守护进程内存 / CPU 基准 |
| `tools/smoke_collect.py` | 实时打印前台切换（毫秒级） |
| `tools/bg_probe.py` | 后台活跃判定探针（含受控对照实验），用来标定阈值 |
| `tools/smoke_daemon.py` | 守护进程链路自检 |
| `tools/make_shortcut.py` | 建桌面快捷方式 |

一次性跑全部：`验证-自检全部.bat`

## 隐私

完整说明见 **[PRIVACY.md](PRIVACY.md)**。三句话版本：

1. 只采集"哪个程序用了多久"所需的字段；**不采集窗口标题、键盘、剪贴板、截屏、文件内容**。
2. 数据只存 `%APPDATA%\UsageWatcher\`，不写程序目录，不改注册表。
3. **源码里没有任何网络代码**——不监听端口、不建连接、不上报。可以自己用 `audit.py` 验证。

## 安全

见 **[SECURITY.md](SECURITY.md)**。要点：不请求管理员权限、不注入进程、不使用任何 IPC 通道
（无端口、无命名管道）、全部参数化 SQL、外部数据按不可信输入处理。

## 已知限制

见 [说明文档.md](说明文档.md) 第四节。**统不到**：系统进程、受保护进程、
虚拟机/模拟器内部的程序、以其他用户账户运行的程序。
**精度受限**：浏览器分不出标签页、UWP 归因可能不准、加速器/代理纯转发流量
不计入后台（应用自带统计，刻意不重复计）。
